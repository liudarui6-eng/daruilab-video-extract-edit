# 从内容主线到成片

## 语义选段

每条确定一个主题、受众问题、真实开头钩子、核心论证和收束句。钩子可用原片问题、冲突或结论，但随后的内容必须兑现。30 秒通常讲一个点，1 分钟通常包含问题与解答，3–5 分钟可呈现完整案例，30 分钟按主题章节组织；这是策划起点，不是强制模板。

混剪允许重排，但必须保留主语、否定、条件、因果与必要铺垫。删除重复、无信息等待与无关岔题，保留有表达作用的停顿。不得靠剪接制造讲者原本没有的主张。不要截断音节或句尾来凑整秒；若用户要求严格时长，应重新选段或压缩内容。明确允许的时长误差，不默许 1 分钟变成 90 秒。

“仅一小时后”之类约束作用于每一个原片区间，包括开头钩子。输出时间码与源时间码分别保存。

## 剪辑清单 EDL

写 JSON，时间均为秒，按成片顺序列 segments；区间可以重排。所有片段默认为正常速度、硬切，若做变速/交叉转场须另建对应时间轴模型，不能用此脚本误报时长。

```json
{
  "source_duration": 7200,
  "allowed_source_range": [3600, 7200],
  "clips": [{
    "id": "01",
    "title": "一条完整观点",
    "hook": "从来源核对的开场句",
    "target_seconds": 60,
    "tolerance_seconds": 3,
    "segments": [
      {"start": 3900, "end": 3925},
      {"start": 4200, "end": 4235}
    ]
  }]
}
```

`allowed_source_range` 可省略，默认全片；实际从头可用时不要保留示例中的 3600。脚本用法：`python3 scripts/validate_edl.py /absolute/project/edl.json`，输出每段源/输出时间映射；失败退出码为 1。只有来源、时长与清单检查通过后才进入该清单批次。

## 剪辑、字幕与音频

- 先用代表片段测试解码、拼接、字体、字幕框及编码；样片通过后批处理。用户已确认的风格不重复索要确认。
- 混剪每段先重置音视频时间戳；拼接前对齐所需的像素格式、画幅、音频采样率等。仅在必要时统一帧率，依据输入选择；没有固定帧率适用所有原片。
- 保持源画幅，横屏不默认裁竖屏。上下文重要的屏幕演示避免放大到看不到关键内容。
- 字幕基于最终剪辑时间轴生成或依据 EDL 重映射；跨剪点的 cue 要拆分或重转录。随后翻译为英文，保持两种语言 cue 序号、起止时间完全一致。
- 简体中文主行在上，英文较小在下。半透明框包住文本，随分辨率与画面安全区调整字体、行宽和边距；不要遮脸、代码或关键 PPT。检查实际烧录帧，不只检查 ASS 样式文本。
- 人声优先。避免无必要 BGM、夸张转场与闪烁字卡。音量处理按源素材测量，避免削波；短淡入淡出改善剪点但不能吃掉首尾辅音。
- 最终如需通用播放，可选 H.264/AAC MP4 + faststart；质量参数根据输入与用途确定。烧字幕与滤镜不能配视频 stream copy。
- 自动去静音仅作为候选编辑，先预览并复核剪点。不要在字幕时间轴固定后再无映射地改变剪辑。

剪辑完成后按 delivery.md 验收。标题、封面、发布文案只在用户请求时额外交付；不自动上传发布。
