# 素材获取与恢复

## 先判断需要什么

记录原始分享链接、课程标题或视频标识与实际媒体的对应关系。分享链接被粘上中文指令时，只取真实 URL；不要猜测另一门课程。优先检查任务目录中的原片、字幕和已完成记录，核对时长与来源后复用。

仅文稿分析：优先原有字幕，核对字幕语言、覆盖范围及是否自动生成；必要时下载音频。需要屏幕提示词或成片才获取视频。不要为纯文字任务默认下载最高画质大文件。

## 获取路线

1. 本地用户提供的文件或本项目已验证的下载。
2. 工具支持的网站：先列可用字幕/格式，再按质量、音轨、实际体积和兼容性选择。保存稳定来源标识，不把临时 CDN 签名链接当永久来源。
3. 用户已登录的网站：使用其指定浏览器查看实际页面和播放器。必要时通过工具允许的页面或开发者工具界面确认媒体请求。页面登录、播放器播放、媒体文件可访问是三个不同检查点。
4. 浏览器标签接口持续失败时，可尝试可用的原生电脑工具连接同一浏览器；不无限重试。默认同一路径最多三次无进展尝试，随后换路线或说明缺少的具体条件。重新读取 UI 状态，不能复用过期控件编号或固定屏幕坐标。

使用浏览器/电脑工具前遵守其初始化和能力限制；不要通过私自读取浏览器数据库或绕过工具限制取得凭据。访问受限、DRM 或没有授权时停止该获取路线。用户能播放不自动证明可绕过下载保护。

## 流媒体与速度

- 同等可用画质下，优先体积合理、可恢复的直连文件；直连不是必然更快，实际检查大小、速度与音轨完整性。
- 对可直接合法获取的 HLS，优先成熟下载工具。识别主播放列表与媒体列表、音视频分轨、完整 VOD 与仍在直播。未结束的直播不能声称已下载整场。
- 分片下载采用有限并发、有限重试、断点缓存和完成清单。网络失败或签名过期先定位原因，不盲目叠加重试；临时文件保留为未完成状态。
- 合并成功后核对预计时长、轨道和解码，再将 partial 文件标记完成。保留缓存供恢复；空间不足时先说明具体占用，不擅自删除原片。
- 无需画面变动时可重新封装/流复制；字幕烧录、缩放和滤镜需编码。仅改扩展名不算格式转换。精确语句剪切不能靠非关键帧流复制保证。

## 原片检查

用 FFprobe 记录 duration、video/audio codec、width/height、SAR/DAR、帧率和音频采样率。确认空间足够容纳原片、缓存及预计输出。抽查头、中、尾可解码；发现不规则时间戳时才规范化，不统一强制 25 fps。

先发现本地工具和运行时再安装；安装新软件时核实官方来源，避免把旧版本号和平台专属路径固化进通用工作流。
